# kb-v2 踩坑手册

> 本项目开发中真实踩过的坑 + 根因 + 修复方式。**先看症状找编号，再看根因避免复发。**

---

## 1. Reranker 直接按分排序，把正确结果打乱

- **症状**：开启 rerank 后，`async_03` 用例（融合分第 1）被重排到第 7，检索反而变差。
- **根因**：交叉编码器对中文短文本打分普遍偏高且集中（0.85~0.99），直排等价于"rerank 分微差决定一切"，把融合排序积累的跨通道证据丢弃。
- **修复**：**加分微调**——以池内最低 rerank 分为基线，`分差 × weight(0.15→0.25)` 并入融合分，融合排序仍主导。
- **验证**：关 rerank 时 W07 融合 0.5616；开 rerank 后 rerank=0.8615 / 融合=0.6906（+0.129）。以后凡是引入新排序器，先想"融合还是颠覆"。

## 2. 候选池太小，Reranker 无米下锅

- **症状**：无标签时候选池只有 4+10=14 条，整本书 PDF 的正确答案 chunk 排到 35 名，**进不了池**，rerank 再准也没用。
- **根因**：向量召回只取 top_k（4 条），BM25 只取 10 条。整本书 PDF 的正确答案 chunk 向量分系统性偏低。
- **修复**：统一 `fetch = k × 5` → 进一步 `k × 8`；`bm25_top_k` 10 → 30；`rerank.top_n` 30 → 50（精排窗口必须覆盖 PDF 正确章节的实测位置 15~22 名）。
- **教训**：召回漏斗的顺序是"召回广度 → 融合排序 → 精排"，上游不足时下游无法补偿。诊断顺序：先确认答案在不在候选池，再谈重排。

## 3. huggingface.co 直连超时，模型加载卡死

- **症状**：新 Python 进程加载 bge 模型时，`HTTPSConnectionPool(host='huggingface.co') ConnectTimeoutError`，重试 5 次 × 多个文件，一次卡几分钟甚至挂死。
- **根因**：`sentence_transformers` 每次启动会 HEAD 请求 HF 检查远程更新；本项目网络环境无法直连 huggingface.co。
- **修复**：运行前设置 `$env:HF_ENDPOINT="https://hf-mirror.com"`（Windows PowerShell）或 `export HF_ENDPOINT=https://hf-mirror.com`（Linux）。
- **验证**：镜像下模型加载秒级完成，benchmark 全流程可跑。
- **教训**：任何涉及 HF 模型下载/加载的脚本，第一行就该设置镜像；已写入各 benchmark / 诊断脚本的运行说明。

## 4. 图谱首屏空白（NaN 坐标）

- **症状**：图谱页首屏全空白，控制台无报错，刷新无效。
- **根因**：`settle()` 同步预收敛调用了**无参** `step()`，`dt = undefined` → 坐标计算得到 NaN → `draw` 静默失败（canvas 画 NaN 不报错）。
- **修复**：`step(dt)` 加兜底 `dt = dt ?? 1`；`settle()` 先同步收敛 150 轮 + 立即 `draw` 一帧（rAF 在无焦点窗口会被暂停，图不能等）；`focus/visibilitychange` 事件重画；`init` 防重入。
- **验证**：修复后领域分簇清晰渲染，标签不打架。

## 5. 力导向图卡死 / 拖拽掉帧

- **症状**：勾选实体层后 1259 节点全量渲染，页面卡死；随后优化到"能渲染但拖拽 30 秒后掉到 2 帧"。
- **根因**（两层）：
  1. 斥力 O(n²)：1259 节点 = 158 万对/帧。
  2. mousemove 每秒触发 100+ 次，每次都触发全量重绘（2202 条边逐条 stroke）。
- **修复**：
  - 网格空间分区：`cell = max(70, minD×4)`，只算同格 + 邻 8 格 → O(n·k)。
  - 边一次 path 批量 stroke + 高亮层 2 次绘制。
  - 动画帧数自适应（>600 节点 350 帧）。
  - 拖拽改用 **rAF 渲染循环节流**：一帧最多一次重绘；拖拽中隔帧跑轻量物理（节点固定、邻居跟随）；hover 高亮合并到 rAF；tip DOM 只在目标变化时更新。
- **验证**：1259 全量渲染主线程 jsCostMs=2.4ms/帧；拖拽流畅。
- **教训**：前端性能问题的标准排查顺序——量级分析（O(n²)？）→ 高频事件节流 → 合并 DOM/绘制。

## 6. BM25 参数微调无效——先诊断再调参

- **症状**：把 `bm25_top_k` 10→20、`graph_boost` 0.05→0.08，跑 benchmark **指标纹丝不动**（0.826/0.522 不变）。
- **根因**：混淆组失败的原因根本不在 BM25 数量/权重——**候选池里抓到的 PDF 片段本身就是错的**（reranker 给它们打 0.03~0.1 的近乎零分），真正讲 LangChain Agent 的章节 chunk 没进池；且全书根本没有该内容（见坑 #7）。
- **修复**：写诊断脚本打印"候选池内答案位置 + rerank 分"，数据说话：
  ```python
  # 关键诊断：答案在候选池吗？排第几？rerank 分多少？
  pdf_pos = [i for i, h in enumerate(hits) if exp in h["source"]]
  print(pdf_pos, [(h.get('rerank_score')) for h in hits if exp in h["source"]])
  ```
- **教训**：**调参之前先确认瓶颈环节**。参数实验一轮 benchmark 要 5 分钟，盲调 3 轮不如 1 次诊断。

## 7. Benchmark 无效标注——期望答案不存在

- **症状**：`agent_confusion` 组 4 例 hit@1 永远 0.000，怎么优化都不动。
- **根因**：期望源 `AI-Agents-in-Depth-zh-CN.pdf` 全书 316 片段中：`LangChain` 仅 4 处（且非教程内容）、`ReAct prompt` 0 处、`langgraph` 3 处。**期望答案在源里根本不存在**，检索再强也找不到。
- **修复**：全文扫描验证每个用例的期望源：
  ```python
  col.get(include=["documents", "metadatas"])  # 全量扫描
  Counter(m["source"] for i,m in enumerate(metas) if kw in docs[i])  # 关键词分布
  ```
  把 4 个无效标注改到内容真实存在的文档（W02/W03/W07/13-GitHub），每个修正写明依据。
- **验证**：修正后同参数下 filtered hit@1 0.826 → 0.913（+0.087）。
- **教训**：**评估集标注 = 测试代码的一部分，要定期做"标注有效性校验"**。指标长期卡死不动，先怀疑标注，再怀疑检索。

## 8. PowerShell 读 UTF-8 JSON 乱码/解析失败

- **症状**：`Get-Content x.json -Raw | ConvertFrom-Json` 报"传入的对象无效"或中文全乱码。
- **根因**：PowerShell 5 默认用 ANSI 读无 BOM 的 UTF-8 文件，多字节中文破坏 JSON 结构。
- **修复**：改用 Python 处理：
  ```python
  with open("x.json", encoding="utf-8") as f: json.load(f)
  ```
  或 `Get-Content -Encoding utf8`。**所有 json 的读写一律走 Python**。
- **另注**：PowerShell 控制台输出中文脚本时用 `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')`，否则 print 中文报 UnicodeEncodeError。

## 9. GitHub 推送失败（https.proxy 缺失）

- **症状**：`git push` 到 GitHub 连接被 reset，报错无明确指引。
- **根因**：git 全局配置有 `http.proxy` 但**缺 `https.proxy`**，HTTPS 直连被网络重置。
- **修复**：
  ```
  git config --global https.proxy http://127.0.0.1:7892
  ```
- **验证**：补上后连续多个 commit 推送成功。

## 10. 浏览器缓存旧 JS，改完不生效

- **症状**：改了 graph.js 刷新页面还是旧行为（首屏空白修好但刷新仍空白）。
- **根因**：浏览器 / 内置浏览器缓存了旧版本 JS 文件。
- **修复**：`graph.html` 引用脚本加版本号 `?v=2/3/4`，每次改 JS 升版本号强制刷新。
- **教训**：前端资源改动后验证"用户真实看到的一层"，不只看文件内容。

## 11. Reranker 模型下载走代理/镜像才能成功

- **症状**：`BAAI/bge-reranker-base`（约 1GB）首次下载失败。
- **根因**：同坑 #3，HF 直连不可用。
- **修复**：`HF_ENDPOINT=https://hf-mirror.com` 下载；下载到缓存后正常加载。
- **注意**：模型约 1GB，首次下载耗时取决于镜像速度；下载完成后 `_model` 进程内只加载一次。

## 12. 工具池"工具数 = 0"

- **症状**：`/api/tools` 返回工具数 0，明明注册了 4 个工具。
- **根因**：工具池由 `import kb.agents.tools` 触发注册；main.py 未 import 该模块时池是空的。
- **修复**：`main.py` 加 `/api/tools` 时显式 `import kb.agents.tools`。
- **教训**：注册式单例必须确认"注册入口被触发"，测试 API 前先验证注册链路。
